## 2. 问题清单

### 2.1 已修复

| # | 等级 | 位置 | 问题 | 影响 | 修复 |
|---|---|---|---|---|---|
| 1 | 🔴 | `webhook_routes.py` `_normalize_scope_target()` + create/update 调用处 | 对 `scope=global` 返回 `None`，调用方把 `None` 判定为「格式错误」——**合法值与错误值共用一个返回值** | **任何全局 webhook 都存不进去**（400「scope_target 格式错误」）。课表/天气/系统的默认范围就是全局，等于管理端绝大多数 webhook 创建/编辑失败 | 新增哨兵 `_INVALID_SCOPE_TARGET` 区分「global（合法，忽略目标）」与「格式非法」；错误文案抽为 `_SCOPE_TARGET_FORMAT_ERROR` |
| 2 | 🔴 | 同文件 create / update | **写入层没有围栏**：`scope=global` + `modules` 含 `electricity`（或 `all`）的配置可以直接存库，只有投递层会拒发 | 绕过前端直调 `POST/PUT /admin/webhooks` 即可落库隐私越界配置；投递层虽兜住，但库里会留一条「看起来在发、实际被跳过」的脏配置 | 新增 `_check_scope_conflict()`（含电量或 `all` 时禁止 global、禁止空受众），create 与 update 都调用；**update 按「与库内现值合并后的最终配置」判定** |
| 3 | 🟠 | `miniapp_routes.py` `create_my_webhook` | 学生自建 webhook **无数量上限** | 每条 webhook 都会收到课表/天气广播副本（`fanout_broadcast_webhooks` 遍历所有非全局 webhook 逐条发）→ 可被滥建放大出站请求与库行数，也会把自己的机器人打到微信限流 | 新增 `_MAX_WEBHOOKS_PER_STUDENT = 10` |
| 4 | 🟡 | `webhook_routes.py` create/update 的 `modules` 校验 | `data["modules"].split(",")` 假定入参是字符串；传数组会 `AttributeError` → **500** | 畸形请求打出 5xx，且错误信息无指导性 | 显式 `isinstance(..., str)` 校验 → 400 并给出格式示例（不做隐式兼容，避免掩盖调用方错误） |
| 5 | 🟡 | `webhook_routes.py` update 的 `scope_for_target` | 只传 `scope_target`（不带 `scope`）时按 `"global"` 规范化 → 直接返回 `None` → 400 | 合法部分更新被误拒；PUT 语义不成立 | 改为按**库内实际 scope** 规范化 |
| 6 | 🟡 | 同文件 update | 换 `scope` 类型（student ↔ dorm）却不带新受众时，旧 `user_id` 目标会残留并被当作「宿舍值」 | 语义错位：宿舍名成了 `"7"`，投递时匹配不到任何学生（静默不发） | 换类型且未给新受众 → 清空目标，由围栏要求重新指定 |
| 7 | 🟡 | `admin-frontend/src/pages/Webhooks.tsx` 6 处 `catch` | 用固定文案「保存失败 / 删除失败」等，**吞掉后端拒绝原因** | 围栏返回的「接收范围不能为全局…」等提示无法到达管理员，围栏形同静默 | 改用项目既有约定 `showApiError(error, "…")`（`Blacklist.tsx` 等已如此） |
| 8 | 🔴 | `app/services/delivery_service.py` `_process_pending_tasks` 的定向 webhook 补发 | 补发 `fanout_broadcast_webhooks(...)` 直接写在 `adapter.send()` 之后、状态落库之前，且无 `try`；触发条件是 `message.get("msgtype")`（未判 `isinstance(message, dict)`） | 补发一旦抛异常（或 `message` 是字符串）会被外层 `except` 捕获 → 把**已推送成功**的任务 `update_status(..., "retrying")` → 重试造成**重复推送**。违反 `webhook_push_service` 模块 docstring 自述的「失败静默、绝不影响主推送流程」 | 整段补发包进 `try/except Exception`，异常只记 `WARNING`、**不改任务状态**；加 `isinstance(message, dict)`；内容取值改 `(message.get("markdown") or {}).get("content", "")` |

### 2.2 已核实无问题（本次未改动）

| 项 | 核实结论 |
|---|---|
| 小程序 webhook 越权 | 5 个端点（list/create/update/delete/test）**全部** `@student_required` + `_student_webhook_owned()` 归属校验，越权统一按 404 返回；list 按 `owner_user_id` 过滤 |
| 学生端接收范围篡改 | 创建与更新都由服务端**强制覆写** `scope="student"`、`scope_target=[本人 user_id]`、`owner_user_id=本人`；客户端传 `global` 或他人 id 一律无效（已用桩验证） |
| 学生端 SSRF | 仅允许 `https://` + hostname **精确等于** `qyapi.weixin.qq.com`（`qyapi.weixin.qq.com.evil.com` 这类后缀伪装会被拒）+ 内网/保留网段阻断。注：内网段分支在精确白名单之下实际不可达，属冗余防御，无害 |
| 学生能否自改宿舍 | `dorm` **不在** `PUT /student/profile` 的 `allowed_fields` 白名单内；绑定写 `profile.dorm = roster.dorm`（以名单为准），解绑清空 |
| `dorm` 字段暴露面 | `StudentProfile.to_dict()` / `StudentRoster.to_dict()` 新增 `dorm`，但消费点均为本人接口（`/student/profile`、`bind`）或 `@admin_required` 路由；无跨用户读取路径 |
| 电量报告内容 | `format_{daily,weekly,monthly}_markdown` 只输出该学生的姓名、用电量、各电表读数、剩余电量；**不含 Cookie / 凭据** |
| SQL 注入 | `_expand_dorm_user_ids` 用 ORM `.in_()` 参数化；异常时 fail-closed 返回空集 |
| 投递范围 | `adapter_service` 只把 `scope=global` 的 webhook 纳入模块广播适配器；`fanout_broadcast_webhooks` 跳过 global 避免重复投递 |
| 历史数据误拒风险 | `webhooks.scope` 列有 DB 级 `DEFAULT 'global'`，实测本地库 2 条记录均为 `'global'`、无空串/NULL → 投递层护栏不会误拒历史行 |
| 前端 XSS | 宿舍串 / URL / 姓名均经 React 文本节点渲染，无 `dangerouslySetInnerHTML` |

   命中即为「电量会被跳过」的记录。

## 6. 未修项（需你决策）

| # | 等级 | 问题 | 说明与建议 |
|---|---|---|---|
| 1 | 🟠 | **宿舍值没有学校维度** | `dorm` 是纯字符串（如 `A栋305`）。`_expand_dorm_user_ids` 的 join 条件只保证 roster↔profile 的「学校+学号」一致，**filter 只按 `dorm` 字符串**；`GET /admin/students/dorms` 也是全库去重。若名单含**多所学校**，两校同名宿舍会被合进同一条消息 → 跨校数据泄露。<br>**单校部署（当前形态）无影响。** 若要加固，两条路：①按当前用户/配置的学校过滤；②选项值改成「学校/宿舍」复合串（会改存量数据，需迁移）。 |

| 3 | 🟡 | `test` 端点无独立限流 | 管理员/学生可反复调用测试接口向自己的机器人发消息（学生端已受 10 个上限约束）。建议复用 `Flask-Limiter` 加个频次限制。 |
