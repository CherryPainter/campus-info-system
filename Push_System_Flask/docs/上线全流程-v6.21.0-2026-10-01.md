## 阶段 3：课程脏数据修复

线上 v6.19 的课程数据大概率是脏的（`weeks` 单周、重复行、碎片、`course_key` 为空）。

```bash
cd /opt/Push_System_Flask
# 3.0 先把 4 个脚本从本地 scp 到本目录，然后：
venv/bin/python diagnose_courses.py        # 只读体检：先看清脏在哪、多严重
venv/bin/python backfill_course_key.py     # 回填 course_key（幂等）
venv/bin/python cleanup_courses.py         # 清洗（自动整表备份 courses_bak_<时间戳>）
venv/bin/python _local_verify_key.py       # 复核：0 空 key / 0 不一致
```

**验证点**：`_local_verify_key.py` 输出「空 key 0 行、不一致 0 行」。

**然后触发全学期重爬（脚本替代不了，必做）**：

- 从管理端手动触发一次**整学期爬取**，或等定时任务（默认开启，`CRON_EXPRESSION=0 7,13 * * *`）。
- 行为：按 `(semester_id, course_key)` 更新；`course_key` 为 NULL 的旧行走弱身份兜底并纠正 key；本批未命中的 **`full`** 源行软删（`stale_reconcile`）。
- **盲区**：`daily` 源的重复行不会被清（已由上面的 `cleanup_courses.py` 处理）。

**验证点**：重爬后再跑一次 `diagnose_courses.py`，「单周」行数显著下降；管理端「今日课程」正常显示。

## 附：最容易漏的 5 件事

1. **`pip install -r requirements.txt`** —— 新增 `nh3`，漏了公告/自定义推送正文读写会 fail-closed 直接报错。
2. **`uq_user_notif_ref` 唯一约束** —— `migrate` 不建，得手动。
3. **小程序同批上传** —— 电量接口字段变了，不同批会列表空白。
4. **全学期重爬** —— `weeks` 单周只有重爬能修，脚本修不了。
5. **生产 `.env` 的两个语义变更** —— `QWEATHER_LOCATION` 必须是「经度,纬度」（写 LocationID 会静默回落重庆）、`WEATHER_SCHEDULE_DAILY`（旧名 `QWEATHER_` 前缀失效）；另 `QWEATHER_API_HOST` 必须是账号专属域名（旧公共域名已停服）。
