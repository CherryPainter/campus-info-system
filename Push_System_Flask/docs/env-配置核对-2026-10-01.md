> 起因：核对本地 `.env` 与入库模板 `.env.example` 的差异，随后扩到「全仓代码实读键 ↔ 模板键集合」的完整比对。
> 本文件是该次核对的**判定结论存档**（过程与改动记录见根 `CHANGELOG.md` 的 Unreleased 段）。
> 位置说明：本文件随 2026-10-16 文档整理从 gitignored 的 `技术总结/` 迁入 `Push_System_Flask/docs/`，属入库项目文档。

## 一、核对方法（三口径）

| 口径 | 怎么取 | 能发现 |
| --- | --- | --- |
| ① 代码实读点 | `os.getenv("KEY", 默认)` 的**真实位置**，要全仓找（含 `app/cqie-course-timetable/` 子项目） | 键名漂移、死键 |
| ② 入库模板 | `.env.example` 的键集合 | 模板缺键 / 模板列了死键 |
| ③ `Config` 声明 | 该属性是否真的被 `config.py` 赋值 | **假开关**（`getattr(Config,"X",默认)` 在 `X` 未声明时恒返回默认值） |

**核心口径：「`.env` 里写了」≠「生效」。**

本次规模：全仓代码读取键 **87 个**，`.env.example` 键 **66 个**。

### 脚本盲区（必须知道）

通过**变量名常量**间接读取的键，正则扫描**抓不到**：

```python
# app/utils/url_guard.py
_URL_GUARD_ALLOWED_HOSTS_ENV = "WEBHOOK_URL_ALLOWED_HOSTS"   # :63 定义常量
raw = os.getenv(_URL_GUARD_ALLOWED_HOSTS_ENV, "") or ""      # :68 才 getenv
```

→ `WEBHOOK_URL_ALLOWED_HOSTS` 在第一版扫描里被**误报为「模板列了但没人读」**。
**判定死键前，必须再按字面量 grep 一次确认。**

## 三、已订正的键名 / 说明漂移

| 项 | 原（错） | 正 | 依据 |
| --- | --- | --- | --- |
| 天气晨报时间键名 | `QWEATHER_SCHEDULE_DAILY` | `WEATHER_SCHEDULE_DAILY` | 代码只读后者（`config.py:338`）。配了不生效，只因默认值同为 `07:00` 才未暴露 |
| `QWEATHER_LOCATION` 格式 | 「LocationID（默认 101040100）」 | **必须**写 `经度,纬度`（默认 `106.55,29.56`） | `fetcher.py:216-225` 对它 `split(",")` 取前两段当经纬度调预警 API，填 LocationID 会**静默回落**到重庆坐标；管理端 `admin_routes._validate_location` 也强制两段坐标 + 范围校验 |
| `QWEATHER_API_KEY` | 「**必填**」 | 「可选（兼容旧版）」 | `fetcher.py:118-122`：JWT 三件套齐备则走 JWT，**否则**回退用本键，二者二选一 |
| `weather.location_id`（代码注释） | 「坐标 或 LocationID 均可」 | 「必须是『经度,纬度』」 | 同 `QWEATHER_LOCATION`（`module_config.py:126`） |

## 四、判定为「有意不列」的键（不动，避免误补）

| 键 | 不列的理由 |
| --- | --- |
| `COURSE_SPIDER_ENABLED` / `COURSE_PUSH_ENABLED` / `COURSE_ENABLE_BACKGROUND` / `COURSE_SPIDER_INTERVAL_HOURS` / `COURSE_DEFAULT_PUSH_ENABLED`、`QWEATHER_CITY_NAME` | 走**管理端配置页**——`module_config.py:313` 起的 `module_key → Config` 映射表即证据（写 DB 并同步 `.env`） |
| `ENV` / `FLASK_ENV` | 框架/运行时标准变量，不是业务配置 |
| `CORS_ORIGINS` | 兼容旧名，已由 `ALLOWED_ORIGINS` 取代（`config.py:158-159` 是 `os.getenv("ALLOWED_ORIGINS") or os.getenv("CORS_ORIGINS")`），README 已注明 |
| `GUNICORN_BIND` / `WORKER` / `WORKERS` / `TIMEOUT` / `LOGLEVEL` / `ACCESSLOG` / `ERRORLOG`、`GUNICORN_WORKER_ID` | 部署层参数，由 systemd / 进程环境传入，不是 `.env` 的职责 |
| `WEATHER_WEBHOOK` | `config.py:344` 只定义、**无消费方** |
| `APPLY` / `ENV_FILE_PATH` / `XLSX_COURSE_PATH` | 工具脚本（`tools/`）与爬虫子项目的内部参数 |
| `ELECTRICITY_CRAWLER_USER_AGENT` | 代码有内置 UA 默认值；除非被目标站识别，部署者一般不需要改 |

## 六、仍未决 / 未做

- **`QWEATHER_API_HOST`（2026-10-01 已查证并订正，移出未决项）**：原记「代码 `https://devapi.qweatherapi.com` vs 文档 `https://devapi.qweather.com`，是否为书写差异未能确认」。现已实测确认——**不是书写差异**：
  - `devapi.qweatherapi.com`（代码三处兜底值）**DNS 解析失败，域名不存在**（同后缀 `p75khv7wkr.re.qweatherapi.com` 可解析，排除本机网络因素）；
  - `devapi.qweather.com` **已停服**（实测 `403 Invalid Host`），官方公告其于 2026-01-01 停服、`api.qweather.com` 与 `geoapi.qweather.com` 于 2026-06-01 停服；
  - 账号专属 API Host（形如 `xxx.xx.qweatherapi.com`，控制台「设置」页查看）实测 `401 Unauthorized`（Host 有效、仅缺凭据），本机 `.env` 即此形态。
  - 订正范围：`.env.example`（改为「必填」+ 占位符）、`README.md` 环境变量表、`DEPLOY_CHECKLIST.md` 的 `.env` 模板段、`DEPLOY_LINUX.md` 必填表与 401/403 排障段；代码 4 处兜底值改空串（`config.py:333`、`tasks.py:101`、`admin_routes.py:552`、`fetcher.py:89`）。
  - 另订正 `DEPLOY_CHECKLIST.md` 天气段三处与 `.env.example` 的旧口径不一致：`QWEATHER_LOCATION=101040100`、`QWEATHER_LATITUDE/LONGITUDE`、`QWEATHER_SCHEDULE_DAILY`。
- **`QWEATHER_LATITUDE/LONGITUDE` 是否要让它们真正生效**：需同时改 `config.py`（声明属性）**和** `QWEATHER_LOCATION` 的默认值（改为空，让 `tasks.py` 的回退分支可达）——属功能决定，未动。
- **`docs/DEPLOY_CHECKLIST.md` 未全面复核**：只修了版本号（v6.11.2→v6.20.0）、旧键名（`CORS_ORIGINS`→`ALLOWED_ORIGINS`）、死步骤（`cp .env.linux .env`）三类明确错误。该文档整体仍是 2026-06-25 的检查结论，其中的**代码行号引用**（如 `config.py:122`、`__init__.py:56`）与新增环境变量**未逐条复核**。
- **`README.md` 目录树里的其他文档**（`DEPLOY_LINUX.md`、`UV_DEPLOY.md`、`安全配置指南.md`）尚未核对其与当前代码的一致性。
